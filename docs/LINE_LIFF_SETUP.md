# จองทริปบน LINE OA ด้วย LIFF — คู่มือติดตั้ง

ระบบนี้ให้ลูกค้าจองทริปจากภายใน LINE OA ผ่าน **LIFF** (เว็บแอปที่ฝังใน LINE)
โดยใช้ business logic / API / ระบบจ่ายเงิน QR + สลิป ของ backend เดิมทั้งหมด

```
ลูกค้ากดปุ่มใน Rich Menu  →  เปิด LIFF (public/liff/)
   → liff.getAccessToken()  →  POST /api/v1/auth/line/liff
   → ได้ Sanctum token  →  เรียก /trips, /bookings ฯลฯ ตามปกติ
```

ส่วนที่โค้ดในรีโปจัดการให้แล้ว:
- **Backend** — endpoint `POST /api/v1/auth/line/liff` ที่ verify access token กับ LINE,
  ผูก/สร้าง user (provider `line`), แล้วคืน Sanctum token
  ([AuthController::lineLiffLogin](../app/Http/Controllers/Api/V1/AuthController.php))
- **Frontend** — เว็บ LIFF แบบ static ที่ [public/liff/](../public/liff/) (ไม่ต้อง build)

---

## 1) สร้าง Channel ใน LINE Developers

1. เข้า https://developers.line.biz/console/ แล้วเลือก/สร้าง **Provider** เดียวกับ LINE OA
2. สร้าง **LINE Login channel** (ไม่ใช่ Messaging API channel)
   - Channel type: *LINE Login*
   - App types: เลือก **Web app**
3. ในแท็บ **LINE Login** ของ channel นั้น ให้ผูกกับ **LINE Official Account** ของคุณ
   (Linked OA) เพื่อให้ปุ่ม/Rich Menu ใน OA เปิด LIFF ได้
4. จดค่า **Channel ID** และ **Channel secret** ไว้

> ถ้าคุณเคยตั้ง LINE Login (เว็บ) ไว้แล้ว ใช้ channel เดิมได้เลย —
> `LINE_LIFF_CHANNEL_ID` จะ fallback ไปใช้ `LINE_CLIENT_ID` ให้อัตโนมัติ

## 2) เพิ่ม LIFF app เข้าไปใน channel

1. ในแท็บ **LIFF** ของ LINE Login channel กด **Add**
2. ตั้งค่า:
   - **Size**: `Full`
   - **Endpoint URL**: `https://<โดเมนของคุณ>/liff/`
     (เช่น `https://luilaykhao.com/liff/` — ต้องเป็น **HTTPS**)
   - **Scopes**: ติ๊ก `profile` (และ `openid` ถ้าต้องการ)
   - **Bot link feature**: เปิด `On (Aggressive)` ถ้าอยากให้ลูกค้าแอด OA ตอน login
3. กด Add แล้วคัดลอก **LIFF ID** (รูปแบบ `1234567890-AbCdEfGh`)

## 3) ตั้งค่า backend (.env)

```env
LINE_CLIENT_ID=<Channel ID ของ LINE Login channel>
LINE_CLIENT_SECRET=<Channel secret>
# ใส่เฉพาะเมื่อ LIFF อยู่คนละ channel กับ LINE Login เดิม ไม่งั้นเว้นว่างได้
LINE_LIFF_CHANNEL_ID=
```

`LINE_LIFF_CHANNEL_ID` คือ channel ที่ backend จะใช้ตรวจว่า access token ที่ส่งมา
ถูกออกให้แอปเรา (กันคนเอา token จากแอปอื่นมาสวมรอย) เว้นว่าง = ใช้ `LINE_CLIENT_ID`

## 4) ตั้งค่า frontend (public/liff/config.js)

แก้ [public/liff/config.js](../public/liff/config.js):

```js
window.LIFF_CONFIG = {
  liffId: '1234567890-AbCdEfGh',          // LIFF ID จากขั้นตอนที่ 2
  apiBaseUrl: location.origin + '/api/v1', // ปกติไม่ต้องแก้ ถ้า host รวมกับ backend
};
```

ไฟล์ใน `public/liff/` เสิร์ฟตรงจาก Laravel — แก้แล้ว deploy ได้เลย ไม่ต้อง build

## 5) ตั้ง Rich Menu ใน LINE OA

ทำผ่าน **LINE Official Account Manager** (manager.line.biz) → Rich menu → สร้างใหม่
- เพิ่มปุ่ม "📅 จองทริป"
- Action: **Link** → URL = `https://liff.line.me/<LIFF_ID>`
  (ลิงก์ `liff.line.me/<LIFF_ID>` จะเปิด LIFF ในแอป LINE ให้อัตโนมัติ)

ลูกค้ากดปุ่มนี้ → เปิดหน้าจองในแอป LINE → login อัตโนมัติ → เลือกทริป → จอง

---

## ทดสอบ

- **บนมือถือ**: เปิดลิงก์ `https://liff.line.me/<LIFF_ID>` ในแอป LINE
- **บนเดสก์ท็อป (dev)**: เปิด `https://<โดเมน>/liff/` ในเบราว์เซอร์ ระบบจะ redirect
  ไป LINE login แล้วกลับมา (ต้องเป็น HTTPS — สำหรับ local ใช้ ngrok/Cloudflare Tunnel)
- ฝั่ง backend ทดสอบ logic ได้ด้วย `php artisan test --filter LineLiffLoginTest`

## ขอบเขตปัจจุบัน

หน้า LIFF ทำได้เท่าหน้าเว็บทั้งเส้นทาง "เลือกทริป → จอง → จ่าย → ดูแลใบจองหลังจอง"
กติกาในนี้ต้องตรงกับ `resources/js/pages/BookingPage.vue` และ `PaymentPage.vue` เสมอ
ไม่งั้นลูกค้าที่จองผ่าน LINE จะได้ใบจองคนละแบบ

ไฟล์ (ไม่มี build step ทั้งหมด แก้แล้ว deploy `public/liff/` ได้เลย):

| ไฟล์ | หน้าที่ |
| --- | --- |
| `app.js` | helper กลาง (api/el/esc/baht/thaiDate/render/appbar/mmss/askConfirm), login, deep link, หน้ารวมทริป, หน้ารายละเอียดทริป, คิวรอที่นั่ง, แชร์ทริป |
| `booking.js` | ขั้นตอนการจอง 3 ขั้น + ปักหมุดจุดรับ + เอกสารแนบ + ร่างการจอง |
| `payment.js` | หน้าชำระเงินครั้งแรก + ชำระรายการที่ค้าง (ยอดคงเหลือ/ค่างวด/ส่วนแบ่ง) |
| `bookings.js` | การจองของฉัน + คิวรอของฉัน + หน้ารายละเอียดการจองและการจัดการทั้งหมด |

### เข้าแอป

`routeFromEntry()` อ่านพารามิเตอร์ตอนเปิด — `?trip=slug` ลงหน้าทริป, `?booking=REF`
ลงหน้ารายละเอียดการจอง, `?page=bookings` ลงการจองของฉัน ไม่มีอะไรลงหน้ารวมทริป
เปิดผ่าน `liff.line.me/{id}?...` LINE จะยัดของเดิมมาที่ `liff.state` อีกชั้น จึงแกะสองชั้น
ใช้กับ Rich Menu และลิงก์ที่เพื่อนแชร์ได้ทันที

### หน้ารวมทริป

ค้นหา, แผ่นตัวกรอง (ปลายทาง/ภาค/ประเทศจาก `/trips/destinations`, ประเภทจาก
`/categories`, ระดับความยาก, ระยะเวลา, เรียงตาม) และโหลดหน้าถัดไปได้

### หน้ารายละเอียดทริป

หัวเรื่อง + ระดับความยาก/ระยะทาง/ความชัน/คะแนนรีวิว, ปุ่มแชร์เข้า LINE
(`shareTargetPicker` ถ้าใช้ได้ ไม่งั้นคัดลอกลิงก์), รายการรอบเดินทาง (ราคาแฟลชเซล,
ป้ายการันตีออกเดินทาง, พยากรณ์อากาศ, ปุ่มจอง/จอยทริป/ขอคิวรอ) แล้วตามด้วย 4 แท็บ:

- **ภาพรวม** — คำอธิบาย, ไฮไลต์, ราคานี้รวม/ไม่รวมอะไร, แกลเลอรี, วิดีโอ,
  วีซ่า+เบอร์ฉุกเฉิน (ทริปต่างประเทศ), นโยบายยกเลิก, ทริปที่คล้ายกัน
- **กำหนดการ** — `itinerary` ทั้งแบบแบ่งช่วง (sector) และแบบรายวันของเดิม
- **เตรียมตัว** — `preparations`, `must_know.remarks`, FAQ แบบพับได้
- **รีวิว** — คะแนนเฉลี่ย + รีวิวจาก `/reviews?trip_id=`

### ขั้นตอนการจอง

1. **เลือกประเภทรถ** (รอบที่วิ่งทั้งบัสและตู้ — ผังและราคาเป็นของคัน สลับคันแล้ว
   คืนที่นั่งคันเดิมให้อัตโนมัติ) → **ผังที่นั่งจริง** (แถว/คอลัมน์/ทางเดิน/ที่นั่งคู่
   คนขับ/แถวหลังนั่งกลาง ตาม `SeatLayoutFactory`) พร้อมปุ่มรีเฟรชผัง หรือ
   **ตัวนับจำนวนคน** เมื่อรอบนั้นไม่มีผัง (บิน / จอยทริป / คันที่ทีมงานจัดที่นั่งเอง)
   → **จุดขึ้นรถ** (เฉพาะจุดจริงของรอบ ไม่มีตัวเลือก "จุดนัดหมายหลัก" — ตรงกับเว็บ
   ที่บังคับให้เลือกจุดขึ้นรถเมื่อรอบนั้นมีจุดให้เลือก) พร้อมไกด์ประเภทรถรับ-ส่ง
   และ **ปักหมุดจุดรับเอง**
   (Leaflet + ค้นหาด้วย Nominatim + ปุ่มตำแหน่งฉัน)
2. **ข้อมูลผู้เดินทาง** — ครบชุดเดียวกับเว็บ: สัญชาติ, เลขบัตรประชาชน (ตรวจ checksum),
   พาสปอร์ต (บังคับเหลืออายุ 6 เดือน), วันเกิด, กรุ๊ปเลือด, ฮาลาล, แพ้อาหาร,
   หมายเหตุสุขภาพ, ผู้ติดต่อฉุกเฉิน, ข้อมูลดำน้ำ, **จุดขึ้นรถรายคน**,
   **เอกสารแนบตาม `trip.document_requirements`**, ปุ่ม "ข้อมูลของฉัน" /
   "สมุดผู้ร่วมเดินทาง" / "คัดลอกจากคนที่ 1", และจองให้ตัวเอง/ให้เพื่อน
3. **สรุป** — บริการเสริม + อุปกรณ์เช่า (เลือกเป็นจำนวน), จองเป็นกลุ่ม,
   **โค้ดส่วนลดที่ตรวจกับ `/promotions/validate`**, แผ่นเงื่อนไขที่ต้องติ๊กยอมรับ

ล็อกที่นั่งตอนออกจากขั้นที่ 1 มี**แถบนับถอยหลัง**ตาม `expires_at` ที่หลังบ้านส่งมา
หมดเวลาแล้วเก็บร่างไว้ให้แล้วพากลับไปเลือกใหม่ · กดย้อนออกจะ**คืนที่นั่ง**ทันที ·
เอกสารแนบส่งตามหลังการจอง (ต้องมี `booking_ref` ก่อน) · จองหลายคนจะถามว่าเก็บ
ผู้ร่วมเดินทางไว้ใช้รอบหน้าไหม

### ชำระเงิน

**ครั้งแรก** เลือกได้ตามที่รอบเปิด — เต็มจำนวน / มัดจำ / ผ่อนชำระ
QR อยู่บนสุดของหน้าและออกให้เองทันทีที่เปิด (ตัวเลือกรูปแบบการชำระอยู่ใต้ QR) —
คนที่เพิ่งกรอกข้อมูลเสร็จมาที่หน้านี้เพื่อสแกนจ่าย ไม่ใช่เพื่ออ่านสรุป คำถามเรื่อง
เก็บผู้ร่วมเดินทางไว้ใช้รอบหน้าจึงถูกเลื่อนไปถามหลังจ่ายเงินเสร็จ ไม่มาคั่นหน้า QR
**รายการที่ค้างบนใบที่ยืนยันแล้ว** — ยอดคงเหลือ, ค่างวดที่ 2 เป็นต้นไป, ส่วนแบ่งกลุ่ม

**ยอดทุกตัวมาจากหลังบ้านเสมอ**: ครั้งแรกจาก `booking.payment_options` (PaymentQuote)
ส่วนรายการที่ค้างจากแถวที่บันทึกไว้ผ่าน `GET /payments/{ref}/promptpay?purpose=…`
วาดตาม `booking.payment_gateway.provider`:

- `beam` — ออก QR ให้ทันทีที่เปิดหน้า, ปุ่มแอปธนาคารตาม `payment_gateway.methods`
  (ส่ง `device_type`), งวด/ส่วนแบ่งส่ง `installment_id`/`share_id` ชี้แถวปลายทาง,
  poll `/payments/beam/{id}`, สลับเป็น "กำลังตรวจสอบการชำระเงิน" (`?sync=1` ทุก 2 วิ)
  ทั้งจากปุ่ม "จ่ายเงินแล้ว" และจากการกลับมาจากแอปธนาคาร (`visibilitychange`)
  มีปุ่ม "ยังไม่ได้จ่าย", เตือนเมื่อรอเกิน 45 วิ, QR หมดอายุแล้วสลับเป็นปุ่มออกใบใหม่
  และเกตเวย์ล่มตกไปทางโอน+สลิปเอง
- `manual` — QR พร้อมเพย์จากเซิร์ฟเวอร์ + แนบสลิป ปลายทางเป็นคนละ endpoint ของแต่ละแบบ
  (`/payments/charge`, `/payments/charge-balance`, `/payments/charge-installment`,
  `/bookings/{ref}/split/shares/{id}/pay`) · ยอดไม่ตรงจะได้ `pending_review`

### การจองของฉัน + รายละเอียดการจอง

รายการมีแท็บกำลังจะถึง/ที่ผ่านมา และ**คิวรอที่นั่งของฉัน** (ออกจากคิวได้ที่นี่)
หน้ารายละเอียดแบ่ง 4 แท็บ:

- **ทริป** — QR เช็คอิน (เซิร์ฟเวอร์วาดให้ที่ `GET /bookings/{ref}/check-in-qr`),
  ที่นั่ง, ประเภทรถ, จุดขึ้นรถ + ลิงก์แผนที่, จุดนัดพบของรอบบิน, ทีมงานประจำรอบ
  (แตะเพื่อโทร), เพิ่มลงปฏิทิน (.ics ประกอบในเครื่อง)
- **ผู้เดินทาง** — รายชื่อ + เอกสารแนบ (ตามส่งเพิ่มได้ที่นี่)
- **การเงิน** — สรุปยอด, ตารางงวดผ่อน, แบ่งจ่ายกลุ่ม (เริ่ม/ส่งลิงก์ให้เพื่อน/ยกเลิก),
  ใบเสร็จ
- **จัดการ** — เปลี่ยนจุดขึ้นรถ, เลื่อนไปรอบอื่น, แชร์ลิงก์ติดตามให้ที่บ้าน, ยกเลิกการจอง

ยอดที่ยังค้างจะขึ้นเป็นแถบพร้อมปุ่มจ่ายไว้บนสุดของหน้าเสมอ

## เทสต์

`npm run test:liff` รันไฟล์จริงใน `public/liff/` บน jsdom โดย mock ทั้ง LIFF SDK และ API
(`tests/Liff/*.test.mjs` + `support.mjs` — แยกจาก PHPUnit ซึ่งอ่านเฉพาะ `tests/Unit`
กับ `tests/Feature`) ครอบคลุม: เส้นทางจอง-จ่ายเต็มเส้น, จอยทริป, รอบบิน/ทริปต่างประเทศ,
โอน+สลิป, คิวรอที่นั่ง, ทุกแท็บของหน้าทริปและหน้ารายละเอียดการจอง, ยอดคงเหลือ,
ค่างวดผ่าน Beam, แบ่งจ่ายกลุ่ม, ยกเลิก/เลื่อนรอบ และ deep link

## ยังไม่ได้ทำ

เขียนรีวิว, Passport/แต้มสะสม, ชวนเพื่อน, ซื้อเป็นของขวัญ, ศูนย์ช่วยเหลือ, การแจ้งเตือน
— ของพวกนี้อยู่ในแอปลุยเลเขาและเว็บไซต์ตามเดิม
